# Cairn Context

[简体中文](README.zh-CN.md)

A small Codex Skill for keeping durable project decisions in a repository that you own and control.

This public repository contains only the reusable Skill and a repository template. Your identity, project context, and decisions live in a separate local or private repository generated by the installer.

The Skill instructs the Agent to:

- read only decisions relevant to the current task (by the Agent's own judgment — there is no programmatic retrieval yet);
- distinguish confirmed decisions from inclinations, questions, and temporary experiments;
- ask for confirmation once when the signal is genuinely ambiguous;
- preserve revisions, revocations, and decision history through a `supersedes` chain;
- record user corrections to a feedback log.

These are behavioral instructions, not enforced guarantees. How well they work depends on the Agent model's instruction-following quality.

## Current limitations

- **No retrieval.** The Agent decides which decision files to read by scanning filenames and titles. There is no search index, embedding, or programmatic relevance ranking.
- **No learning.** Corrections are appended to `protocol/benchmark/feedback.md`, but nothing reads that log to change future behavior. The feedback mechanism is a record, not a closed loop.
- **No validation.** There is no tooling to check whether a decision file has correct frontmatter, valid references, or well-formed history chains.
- **Codex-only.** The installer writes to `~/.codex/skills/`. Using the Skill with other Agent frameworks (Claude Code, Cursor, etc.) requires manual adaptation.

## Install

Clone this repository, then run:

```bash
bash install.sh \
  --identity "Your Name" \
  --project "your-project" \
  --repository "$HOME/cairn"
```

The installer:

1. creates a local Cairn repository from `template/`;
2. writes `~/.cairn/config.json`;
3. installs the Skill to `~/.codex/skills/cairn-context`.

It refuses to overwrite a non-empty repository or an existing Skill installation.

## Optional 30-minute Git sync

The generated Cairn repository includes an optional macOS LaunchAgent. It commits local changes, rebases onto the remote branch, and pushes every 30 minutes. Conflicts stop the sync and preserve the local commit for manual resolution.

First create a **private** GitHub repository and push the generated Cairn repository:

```bash
cd "$HOME/cairn"
git init -b main
git add .
git commit -m "init: create Cairn context"
gh repo create YOUR_ACCOUNT/cairn --private --source . --remote origin --push
```

Then explicitly enable autosync:

```bash
bash "$HOME/cairn/scripts/setup-autosync.sh"
```

Autosync is never enabled by the Skill installer. When GitHub CLI is available, setup refuses to sync to a repository reported as public.

## Repository layout

```text
~/cairn/
├── AGENTS.md
├── protocol/
│   ├── README.md
│   └── benchmark/
│       ├── feedback.md
│       └── cases.yaml
├── scripts/
│   ├── setup-autosync.sh
│   └── sync.sh
└── projects/
    └── your-project/
        ├── README.md
        ├── state.md
        └── decisions/
```

## Agent integration

The `agents/` directory contains Agent-framework configurations:

- `agents/openai.yaml` — OpenAI Codex integration.

## Privacy boundary

Do not point multiple people at a personal Cairn repository merely to share the Skill. Share this public Skill; keep each person's context repository private. Create a separate team repository only for decisions that are intentionally team-readable.
